# 絶叫焼き・焼成スケジュール v1.10

## 主な機能
- Firebase Authenticationでのアカウント登録、ログイン、ログアウト
- 週間予定の登録、編集、削除、焼成完了チェック
- 商品別数量と4個・8個・16個入りセットの予定登録
- セットごとにカスタード・あんこ・ダブル焼きを選択
- カスタードかあんこを選ぶと、残りの味を翌日の製作数に計上
- ダブル焼きは従来どおり同日に2種類を製作
- 翌日の続き製作を予定表に表示し、完了状態も別に記録
- 週間・日別のカスタード、あんこ製作数を表示
- 土曜日は青系、日曜日と日本の祝日・振替休日は赤系で表示
- 日本の祝日を年ごとに計算し、祝日に挟まれた休日も表示
- 翌日に分けた製作数を含め、週間の実際の焼成数から材料の必要量を計算
- 入力中の予定変更も材料合計に即時反映
- 通常商品と箱入り商品で賞味期限日数を別々に設定
- 期限日に該当する予定カードへ、商品ごとの作成日と期限を表示
- ホーム、予定表、材料、発注期限、賞味期限設定の5タブで画面を整理
- ホームに当日の味別数量と箱入り味別数量を表示
- 材料タブで納品数を入力し、発注単位（袋・箱など）のkg数に応じて実質在庫へ加算
- 未完了の予定分を実質在庫から差し引いた週の材料見込みを表示
- 焼成完了チェックで当日分の材料使用量を実質在庫から減算
- 完了状態を戻すと減算分を在庫へ戻し、予定削除時も完了済みの使用分を戻す
- 発注期限タブに材料ごとの納期・発注単位・発注数・期限を表示
- 発注期限の納期計算で土日祝を除く設定

## 材料計算の基準
予定を入力した日と翌日の実際の焼成数の合計に対し、次の配合を比例換算します。

| 材料 | 400個あたり |
| --- | ---: |
| 玉子 | 3.86 kg |
| デリドール | 666 g |
| パルファンドール | 66 g |
| ヤキマンミックス | 6.66 kg |
| 水 | 400 g |

4個・8個・16個セットごとに、当日の味を選びます。カスタードまたはあんこを選ぶと、当日は選択した味の半分を焼き、残りの味の半分は翌日の製作数に加えます。ダブル焼きは両方を当日に焼きます。保存済みの旧予定はダブル焼きとして扱います。箱入り商品の賞味期限は、翌日分も含めて予定を入力した日を起点に設定日数を加算し、その期限日の予定カードに表示します。

実質在庫は納品のたびに加算し、予定の焼成完了チェックでその日に使う材料分を減算します。材料タブの「納品数」に数量を入力して保存すると、発注期限タブで設定した1発注単位のkg数を掛けて在庫に追加します。「納品後・予定差引後」は実質在庫と、対象週に残っている未完了予定の必要量との差です。予定を未完了に戻すと使用分を在庫に戻し、予定を削除すると、その予定で完了済みだった使用分も在庫に戻します。発注期限は未完了予定の材料使用量を日ごとに累積し、初めて在庫が不足する製作日から仕入れ納期日数を引いて算出します。発注期限タブの「納期計算で土日祝を除く」は初期状態で有効です。有効時は仕入れ納期を営業日で数え、計算後の期限が土日祝に当たる場合は直前の営業日に繰り上げます。チェックを外すと従来どおり暦日で計算します。発注数は週の不足分を1発注単位ごとに切り上げます。発注期限タブでは材料ごとの納期、1発注単位のkg数、単位名（袋・箱など）を設定します。

## 既存のFirebase設定と保存データ
Firebase設定は `firebase-config.js` に含まれています。既存の予定ドキュメントIDとフィールドを維持し、セットごとの味選択を保存する `bundleFlavors` と、翌日分の完了状態を保存する `continuationDone` を追加しています。味選択がない既存データはダブル焼きとして表示します。賞味期限・発注設定・実質在庫・完了済みの材料使用記録は、同じ `bakeSchedules` コレクションの `_settings` ドキュメントに `ownerUid` 付きで保存するため、Firebase設定ファイルと `firestore.rules` の置き換えは不要です。以前の週初在庫が保存されている場合は、初回に最も新しい週の在庫を初期値として引き継ぎ、その週から今日までに完了済みの予定分を一度だけ差し引きます。

## GitHub Pagesで更新する
1. ZIPを解凍します。
2. 既存の `bake-schedule` リポジトリを開き、`app.js`、`index.html`、`style.css`、`README.md` を置き換えます。
3. GitHubで変更をコミットします。
4. Pagesの再公開後、アプリを再読み込みします。

## 新規に公開する場合
1. ZIPを解凍し、ファイル一式をGitHubリポジトリのルートにアップロードします。
2. Settings → Pages → Deploy from a branch → `main` / root を選びます。
3. 公開されたURLを開き、初回はメールアドレスと6文字以上のパスワードで登録します。

## Firebaseを初めて設定する場合
1. Authenticationでメール/パスワード認証を有効にします。
2. Firestore Databaseを作成します（ロケーションは `asia-northeast1` を推奨）。
3. 同梱の `firestore.rules` をFirebase Consoleのルールに設定します。
