# 絶叫焼き・焼成スケジュール v1.8

## 主な機能
- Firebase Authenticationでのアカウント登録、ログイン、ログアウト
- 週間予定の登録、編集、削除、焼成完了チェック
- 商品別数量と4個・8個・16個入りセットの合計換算
- 箱入り商品はカスタードとあんこを半分ずつにして集計
- 週間・日別のカスタード、あんこ製作数を表示
- 土曜日は青系、日曜日と日本の祝日・振替休日は赤系で表示
- 日本の祝日を年ごとに計算し、祝日に挟まれた休日も表示
- 週間の総焼成数から材料の必要量を400個あたりの配合で比例計算
- 入力中の予定変更も材料合計に即時反映
- 通常商品と箱入り商品で賞味期限日数を別々に設定
- 期限日に該当する予定カードへ、商品ごとの作成日と期限を表示
- ホーム、予定表、材料、発注期限、賞味期限設定の5タブで画面を整理
- ホームに当日の味別数量と箱入り味別数量を表示
- 材料タブに週初在庫と週間必要量から計算する理論残数を表示
- 発注期限タブに材料ごとの納期・発注単位・発注数・期限を表示

## 材料計算の基準
週間の焼成予定数（商品別数量と箱入り換算数の合計）に対し、次の配合を比例換算します。

| 材料 | 400個あたり |
| --- | ---: |
| 玉子 | 3.86 kg |
| デリドール | 666 g |
| パルファンドール | 66 g |
| ヤキマンミックス | 6.66 kg |
| 水 | 400 g |

賞味期限は、設定した日数を作成日に加算し、その期限日の予定カードに表示します。通常商品の設定は単品入力分、箱入り商品の設定はセット入力分に適用します。

理論残数は「対象週の週初在庫 − 今週必要量」です。発注期限は週の予定を日ごとに累積し、初めて在庫が不足する製作日から仕入れ納期日数を引いて算出します。発注数は週の不足分を1発注単位ごとに切り上げます。材料タブでは対象週ごとに週初在庫を入力し、発注期限タブでは材料ごとの納期、1発注単位のkg数、単位名（袋・箱など）を設定します。

## 既存のFirebase設定と保存データ
Firebase設定は `firebase-config.js` に含まれています。既存の予定ドキュメントのIDと保存フィールドは変更していません。賞味期限・発注設定と週別在庫は、同じ `bakeSchedules` コレクションの `_settings` ドキュメントに `ownerUid` 付きで保存するため、Firebase設定ファイルと `firestore.rules` の置き換えは不要です。

## GitHub Pagesで更新する
1. ZIPを解凍します。
2. 既存の `bake-schedule` リポジトリを開き、`app.js`、`index.html`、`style.css`、`README.md` を置き換えます。
3. GitHubで変更をコミットします。
4. Pagesの再公開後、アプリを再読み込みします。

## 新規に公開する場合
1. ZIPを解凍し、ファイル一式をGitHubリポジトリのルートにアップロードします。
2. Settings → Pages → Deploy from a branch → `main` / root を選びます。
3. 公開されたURLを開き、初回はメールアドレスと6文字以上のパスワードで登録します。

## Firebaseを初めて設定する場合
1. Authenticationでメール/パスワード認証を有効にします。
2. Firestore Databaseを作成します（ロケーションは `asia-northeast1` を推奨）。
3. 同梱の `firestore.rules` をFirebase Consoleのルールに設定します。
